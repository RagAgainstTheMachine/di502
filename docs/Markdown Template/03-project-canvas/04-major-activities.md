# Major Activities

This page lists the work needed to deliver the project, grouped by life cycle stage. Each activity is marked In Scope or Out of Scope. Activities created by a constraint name it (C-xx) from [Assumptions & Constraints](03-assumptions-and-constraints.md). The order in which activities must happen is in [Dependencies](06-dependencies.md).

| # | Stage | Activity | Description | Status | Jira Task |
|---|---|---|---|---|---|
| 1 | Inception | Define the assistant's purpose, users and success criteria | Done during chartering (see [Project Executive Summary](01-project-executive-summary.md), objectives 1–5). | In Scope | DI502-8, DI502-9, DI502-26 |
| 2 | Inception | Market or competitor analysis of existing chatbots | Not needed for an academic proof of concept. | Out of Scope | |
| 3 | Inception | Write user stories and the User Story Map | Stories for features F1–F7, each with acceptance criteria, priority, story points and an assignee in Jira. | In Scope | DI502-25, DI502-27, DI502-40 |
| 4 | Inception | Build evaluation set v1 (D2) | 30 in-scope and 10 out-of-scope test questions with reference answers and sources, plus a written rule for judging an answer correct. 10 questions are picked at random for the timed test (Objective 1). A second member checks every answer (A-02). Because of C-13, the set is fixed before any experiment. | In Scope | DI502-62 |
| 5 | Inception | Prepare the user sessions and measure the default state (D3) | Check each persona and task list (A-01), then time how long participants take on the 10 timed questions using only the official documents. Because of C-11, participants are recorded only by a pseudonymous ID. | In Scope | DI502-64 |
| 6 | Design and development | Learning spikes and system design | Because of C-04 and C-05: choose the text extraction method, embedding model, search index, language model and web framework for Turkish RAG. Results are kept as spike notes, and the choices are recorded in the System Architecture Design Document. | In Scope | DI502-35, DI502-43, DI502-44, DI502-45, DI502-55, DI502-59, DI502-60 |
| 7 | Design and development | Collect the documents and build the document inventory | Because of C-01 and C-03. Check each website's terms of use (A-05), then record each document's official link, download date and legal status (binding law, policy/plan, guidance, report or institutional policy). The latest download date becomes the collection date. | In Scope | DI502-56 |
| 8 | Design and development | Convert the selected parts of the documents to text (D4) | Because of C-02: only the agreed pages and entries are used, and each selection is written down so it can be repeated. Text is typed by hand where a PDF has no usable text. 10 random passages are checked against the PDFs (A-04). | In Scope | DI502-57 |
| 9 | Design and development | Split, embed and index the documents | Because of C-05. Each passage keeps its document, article or section, legal status, date and official link. Glossary terms are stored as separate entries with their English names, for term definitions (F7). | In Scope | DI502-61 |
| 10 | Design and development | Find the relevant passages and write answers in Turkish | Because of C-04 and C-05. Answers come only from the retrieved passages, are in Turkish, and cite the document and article or section with a link (F1, F2, F7). Each source's legal status is taken from the inventory (F3), and every cited source is checked against the retrieved passages before the answer is shown. | In Scope | DI502-12, DI502-13, DI502-14, DI502-16, DI502-17, DI502-18, DI502-48, DI502-53, DI502-54 |
| 11 | Design and development | Decline out-of-scope and compliance-judgement questions | Because of C-06 (feature F5). Each question is checked before the search. If the documents have no answer, the assistant says so. If a question asks for a compliance verdict, a prediction or details still to be prepared, the assistant says what the documents contain and declines the rest instead of guessing. Checked with the 10 out-of-scope test questions. | In Scope | DI502-50, DI502-51, DI502-52 |
| 12 | Design and development | Web chat page | Because of C-08 and C-11. Shows answers with their sources, legal status and dates, the collection date (F6) and a "do not enter personal data" notice. Remembers earlier questions only while the session is open (F4). Has no personal-data fields. | In Scope | DI502-20, DI502-49, DI502-65 |
| 13 | Design and development | Mask personal data before logging | Because of C-11. ID numbers, e-mail addresses and phone numbers are masked before anything is logged, so logs keep only masked data. Mitigation for R-10. | In Scope | |
| 14 | Verification and validation | Baseline run and experiments | Because of C-13. All 40 questions are run with the saved settings and the results are logged (part of D5). Each later experiment changes one setting and is compared with the baseline. | In Scope | DI502-63 |
| 15 | Verification and validation | MVP evaluation (D7) | All 30 in-scope answers are judged with the D2 rule against the Objective 2 targets. | In Scope | |
| 16 | Verification and validation | Pilot evaluation (D9) | Timed test (Objective 1, compared with D3), post-test survey (Objective 3), legal-status check (Objective 4) and out-of-scope test (Objective 5). Because of C-11, no participant data is stored. | In Scope | |
| 17 | Deployment | Deploy and release the beta (D8) | Because of C-07 and C-09. The alpha web page runs locally; the beta is deployed online with a billing budget alert and given to the pilot participants. | In Scope | DI502-58 |
| 18 | Deployment | Release candidate and live demo (D10) | Because of C-10: the final version is shown at the final presentation on 30/12/2026. | In Scope | |
| 19 | Operation and monitoring | Fix pilot defects and track cloud spending | Because of C-09. Every pilot defect is fixed or listed with a reason (D10). Spending is recorded each sprint against the $100 credit (A-06). | In Scope | |
| 20 | Continuous validation | Automatic monitoring and re-indexing of sources | Because of C-03: the collection is a fixed snapshot with a visible collection date, so automatic updates are not needed. | Out of Scope | |
| 21 | Re-evaluation | Update the charter after reviews (D6) and write the final report (D11) | Every review point gets a change or a written reply. The final report gives each objective's target and measured result, plus lessons learned. | In Scope | |
| 22 | Design and development | Training or fine-tuning a language or embedding model | Because of C-05 and C-09: the project uses RAG with existing models, and the $100 credit does not cover training. | Out of Scope | |
| 23 | Design and development | Documents outside the collection | Because of C-01: only the 8 approved documents are used. This leaves out parliamentary bills, foreign regulation, institutions' internal rules, and the history of Türkiye's AI policy or comparisons with earlier strategies. | Out of Scope | |
| 24 | Design and development | Compliance judgements, predictions and details the documents do not contain | Because of C-06: the assistant does not judge whether an institution's plan or practice complies, does not predict future law or policy, and does not fill in steps a plan says will be prepared later. It says what the documents contain and declines the rest (row 11). | Out of Scope | |
| 25 | Design and development | Languages other than Turkish | Because of C-04: questions, answers and documents are in Turkish. The only exception is the English names of glossary terms (F7). | Out of Scope | |
| 26 | Design and development | User accounts, login, stored personal data, saved conversation history and a mobile app | Because of C-08 and C-11: these would require storing personal data, and the assistant is reached only through a web page. | Out of Scope | |
