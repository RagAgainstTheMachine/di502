# General Recommendations for Documentation and Development

Please note that each individual canvas section also has detailed instructions on what is expected and why. Below are applicable to the whole project.

1. Don't design your project according to the standard Waterfall based KDD approach. Instead adopt the TDSP framework.
2. You can perform many data science-related tasks in parallel. For instance, data collection, database design, candidate model selection, dashboard design (can be iteratively developed and released) etc. These tasks can be incrementally detailed and implemented. In each iteration, they can be verified against a determined criterion. For instance, for dashboard design, you can search for exemplary user interfaces in your domain.
3. Use clear KPI's. Acceptance criteria should be clearly defined and they should be measurable. For this project, a combination of retrieval-based (Precision, Recall, MRR) and RAG performance metrics like the RAG triad should be preferred.
4. You should avoid using adjectives while writing your project document i.e. in business outcomes section. Try to be specific. For instance, don't say that your application will have fast response time, but rather state that it will output more than x tokens per second.
5. You should have a baseline method to compare your model against. If you report a metric relating to RAG without comparing it to a simpler method we cannot judge how well your approach worked. Pick a baseline from relevant literature.
6. Create a glossary of terms if needed.
7. Pay attention to the documentation. For instance, when enumerating items, you can start with verbs. Always spell and grammar check your documents. You can use “Outwrite”, “Grammarly” or “ChatGPT”.
8. Don't increase the scope of the project beyond the first proposal. The objective of this course is to learn how to implement an agile TDSP approach in a data science project and to be able to work in teams.
9. Milestones and Deliverables: While most of your milestones are acceptable, focus on clearly defining deliverables. Make sure they do not necessitate the waterfall approach to achieve.
