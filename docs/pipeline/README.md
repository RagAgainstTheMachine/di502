# Document ingestion

This branch delivers document ingestion and the shared code required by a separate retrieval branch.

| Module | Responsibility | Runs when |
| --- | --- | --- |
| `src/ingestion/` | PDF/Markdown conversion, cleaning, structure-aware chunking, validation, embedding/upload and BM25 index setup | Documents or the index change |
| `src/shared/` | Configuration, file validation, payload projection, Cloud connection and lightweight schema checks | Both |

CLI entry points use `python -m` from the repository root; no `sys.path` changes are required.

## Install

Python 3.11+:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Also install these for document preparation and the full test suite:
pip install -r requirements-ingestion.txt
```

Copy `.env.example` to `.env` in the repository root and fill in the existing
Qdrant URL and database API key. Environment variables take precedence over `.env`.
Credentials are not included in this migration. Retrieval settings, the embedding
model and the processed-data path are read from `config/rag.yaml`.

Some reviewed Markdown files intentionally contain selected AI-related material
rather than their entire PDFs. Source PDFs are not copied into Git. Reviewed MD
corrections include manual PDF checks and are not all automatically reproduced
by Docling. The selected Doc01 chunks come from the PDF-specific profile, not its
alternative Markdown version; the retained source-layout limitations remain
documented in `data/processed/README.md`.

Validate every ready bundle without contacting Cloud:

```bash
python -m src.ingestion.index --output data/processed --all --dry-run
```

To explicitly upload these same bundles (not needed just to start searching):

```bash
python -m src.ingestion.index --output data/processed --all
```

The uploader scopes replacement/removal to the selected document name. It does
not reset the collection. Vectors are generated by Qdrant Cloud Inference using
`intfloat/multilingual-e5-small`, 384 dimensions, cosine similarity. Only the
chunk body is embedded; model prefixes are handled by the inference service.

## Prepare documents

Default output: `data/processed/<document_id>/`. Use a different `--output` to
experiment without replacing ready artifacts.

```bash
# Generic reviewed Markdown example:
python -m src.ingestion.prepare --input data/markdown/doc08_kamu_kurumlari_yapay_zeka_sozlugu.md --document-id doc08-kamu-yapay-zeka-sozlugu --merge-peers --compact-payload --output output/rebuilt

# Parse a PDF to Docling JSON and Markdown, without chunking:
python -m src.ingestion.prepare --input data/raw/example.pdf --convert-only --output output/converted

# Doc01: requires the original PDF; it is not included in this repository.
python -m src.ingestion.prepare --input data/raw/doc01_yapay_zeka_eylem_plani.pdf --profile ai-plan --document-id turkiye_ai_eylem_plani_2026_2030 --output output/rebuilt

# Native numbered recommendations in the reviewed report:
python -m src.ingestion.prepare --input data/markdown/doc05_yapay_zeka_komisyon_raporu.md --document-id doc05-yapay-zeka-komisyon-raporu --merge-peers --compact-payload --exclude-footnotes --numbered-unit-section "5.2 SONUÇ VE ÖNERİ TABLOSU" --numbered-unit-label Öneri --output output/rebuilt

# Reviewed document-specific selections, followed by the generic chunker:
python -m src.ingestion.profiles.kvkk_guide --input data/markdown/doc06_kvkk_rehberi_yapay_zeka.md --output output/rebuilt
python -m src.ingestion.profiles.tubitak_policy --input data/markdown/doc07_tubitak_yapay_zeka_politikasi.md --output output/rebuilt
```

HybridChunker uses source structure and the embedding tokenizer, with a 300-token
budget including model prefixes/special tokens and no fixed overlap. It is not
an embedding-based semantic boundary detector. Source headings are metadata,
not artificial prefixes in embedding text. TOC and heading-only fragments are
excluded conservatively. Short factual answers and responsibility paragraphs
are retained. Parent reconstruction and token bounds are validated.

## Index setup and retrieval hand-off

For a new collection, create its text BM25 index after uploading:

```bash
python -m src.ingestion.setup_hybrid --collection ai_plan_text_only --report output/hybrid_setup.json
```

The existing collection already has this index. Setup preserves the point IDs,
payloads and E5 vectors. The BM25 settings are word tokenization and lowercasing
on `text`, without stemming or stopword removal. Qdrant 1.20+ is required.

Request-time search is intentionally delivered in `feature/hybrid-retrieval`.
It depends on this branch's shared configuration and index schema. See the
[two-branch delivery plan](branch-plan.md).

## Checks

```bash
python -m unittest discover -s tests -v
python -m src.ingestion.index --output data/processed --all --dry-run
```

Tests use in-memory storage and substitute remote embedding inference. They do
not upload test points to Cloud. Tokenizer-dependent tests may download the E5
tokenizer once; ready-bundle validation is offline. Original source extraction
limitations and manually reviewed Markdown are retained as documented above.
